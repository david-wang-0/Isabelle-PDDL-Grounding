# Grounder optimization changelog — 2026-07-12 evening → 2026-07-13

Verified PDDL grounder, branch `verified-sat-planner`. This log covers the optimization sprint from the
evening of 2026-07-12 through 2026-07-13: the RBT fact-index for the datalog closure check, the same
index carried over to the **action-grounding (`cert_ops`) join** (Speed 3), the supporting refactors,
the memory/dedup changes, and the join-reorder work. Each change is its own subsection with more detail
than the ranked reference in
the `verified-grounder-optimizations.md` reference (in the grounding-benchmarks repo).

**Method.** Every proof obligation was driven to green in jEdit (heaps: `Datalog_Graph` for the closure
index, `Grounding_Classical_Common` for the `cert_ops` index) and each milestone was gated by a green
`isabelle build Classical_Grounding` before commit. All commits are local; nothing is pushed. The
exported SML (`SMLCodebase/code/PDDL_SAT_Planner_DFS_Exported.sml`) is regenerated by the gate build, so
each change lands in the compiled binary.

**Design invariant.** Correctness of the executable grounder rests on refinement equalities to an
abstract, index-free specification — never on the join strategy. So every index / reorder change carries
a proof that it computes the *same set* (or the *same list*, where a strict `=` is needed), and the
untrusted↔verified boundary (Nemo oracle, streaming printer) is unchanged.

### 1. Stream the grounded-PDDL printer — `8287275` (07-12 18:50)

**What.** Replace `problemToString` (which materialised the entire grounded output — up to ~10⁶ actions —
as one string) with `problemToStream`, writing each action straight to the output stream, and replace the
O(n²) list-based object dedup with a hash set.

**Why.** The renderer was the residual memory blow-up: the full output string reached ≈14.4 GiB (above an
8 GiB cap) on large tasks, and the object dedup was a quadratic list scan.

**How.** `SMLCodebase/pddl_printer.sml`: `problemToStream` (one action live at a time), hash-set
first-occurrence object dedup.

**Proof / verification.** Untrusted printer — no Isabelle proof. Output verified byte-identical to the
old printer on zeno p01 + 9 further benchmarks.

**Impact.** Renderer memory is now bounded by a single action. The win is by construction and not yet
observable end-to-end on the largest tasks, because `cert_ops` still times out before rendering runs (see
change 5 and the pipesworld note).

**Key definitions.**

| hash-set object dedup | `pddl_printer.sml` | 202–203 | O(n²) `dedup` list scan | distinct object names in first-occurrence order via a `StringHashTable` |

### 2. RBT-indexed datalog closure check (fast path) — `36a60f7` (07-12 23:28)

**What.** The executable datalog **closure check** (verifying the reachability certificate: every clause
firing over the certified facts stays within the facts) gets an RBT fact index, so each body atom is
matched by an O(log F) bucket lookup of only the facts sharing a bound argument, instead of an
O(|facts of the predicate|) linear scan.

**Why.** The closure check evaluates each clause body as a join over the certified facts. The old
`cls_substs`/`body_join` path scanned whole predicate relations and materialised cross-products — the
dominant checker cost (≈80 s → 0.7 s on the worst logistics clause in the prototype).

**How.** `Grounding_Common/Datalog_Graph/Datalog_Certificate_Index.thy`: the `ikey` datatype + its
`linorder`; `build_pidx` (predicate bucket), `build_aidx` (per-argument `(pred, pos, value)` bucket),
`build_findex`; `first_bound`, `cand_facts`, `match_facts_idx`, `body_join_idx`; and
`dl_closure_check_exec_fast`. Installed as a `[code]` equation swapping out `dl_closure_check_exec`, so
the soundness bridge `dl_closure_check_exec_imp` (which mentions only the abstract check) is untouched.
The theory loads *live above* the `Datalog_Graph` heap (it is deliberately not in that ROOT so it stays
editable/hot).

**Proof / verification.** The load-bearing lemma is `match_facts_idx_eq` ("Lemma A"): the index-selected
candidates, filtered by the assoc-list unifier, are exactly the matches of the full predicate scan.
`dl_closure_check_exec_fast_eq` lifts that to the whole check.

**Impact.** The closure check drops off the critical path. This commit is also the anchor (COMMIT-0) of
the sprint — the fast path existed uncommitted and was frozen here before the refactors.

| `body_join_idx` | `Datalog_Certificate_Index.thy` | 275 | `body_join` (unindexed) | body join with each atom's candidates fetched through the index |

### 5. Speed 3 (core): RBT-indexed `cert_ops` action-grounding join — `27b2882` + `cb37c60` (07-13 02:18–02:30)

**What.** *The action-grounding fact-indexing.* Carry the closure index over to the `cert_ops` join that
reconstructs applicable ground operators from the certified reachable facts. New indexed mirror of the
abstract `pjoin`: `first_bound_t`, `cand_facts_t`, `pmatch_atom_idx`, `pjoin_idx`, and
`cert_ops_for_clause_fast`.

**Why.** After action-predicate elimination (Corrêa), the certified datalog model is facts only, and the
ground operators are reconstructed downstream by joining each schema's precondition atoms over the facts
(`cert_ops_of`, a proven-complete over-approximation). The abstract `pjoin`/`pmatch_atom` scanned the
whole predicate bucket `organize_facts p` per atom — the **~400 s logistics bottleneck**. Indexing it
fetches only the candidates that share a bound argument.

**How.** New `Classical_Grounding/Reachability_Analysis/Classical_Cert_Ops_Index.thy` (in the CRA ROOT).
The certified facts are a `(predicate, object) dl_fact list`, so `Fact_Index.build_findex` applies
directly; `organize_facts` is the abstract function-bucket the slow join uses. `term.VAR/CONST` mirror
`id.Var/Cst`; `punify` mirrors `match_ids_al`.

**Proof / verification.** The load-bearing proof is `pmatch_atom_idx_eq` (the Lemma-A analogue): filtering
the index candidates with `punify` yields exactly the matches of the full `organize_facts` scan. It
bridges the RBT buckets to the abstract function bucket via `set_organize_facts_eq` (itself using
`in_orga_organize_facts`) and per-key soundness lemmas (`plookup_build_pred`, `alookup_build_pred`).
Then `pjoin_idx_eq` (induction on atoms) and `cert_ops_for_clause_fast_eq` (set-equality to the abstract
`cert_ops_for_clause`).

**Impact.** The headline win: the ~400 s `cert_ops` join is gone. Measured end-to-end, logistics98-prob01
grounds in ~33 s (vs the prior binary's 59 s). The residual cost is now the enumeration itself, not the
per-atom scan (see the pipesworld note for the join-order blow-up that still bites large instances).

### 8. Memory 6: O(n log n) code equation for `canon` — `9d64419` (07-13 07:50)

**What.** Give `canon` an efficient code equation: `canon_code [code]: canon xs = remdups_adj (sort xs)`.

**Why.** The default `sorted_list_of_set` code is `sort (remdups xs)`, and `remdups` is quadratic — the
dedup over the ~10⁶ grounded actions. Since `canon` sorts anyway, adjacent-dedup of the sorted list is
the same list at O(n log n).

**How.** `PDDL_Orderings.thy`: helper lemmas `sorted_remdups_adj` and `distinct_remdups_adj_if_sorted`
(both by induction on `remdups_adj.induct`), then `canon_code` via `List.sorted_distinct_set_unique`.
(Gotcha banked: `sorted_distinct_set_unique` is shadowed in this repo by a pair-list-specialised version;
the qualified `List.` name is required.)

**Proof / verification.** As above. Installed as a global `[code]` equation, so every interior `canon`
(including Option C's top-level canonicalisation) becomes O(n log n) with no def-body edits.

**Impact.** O(n²) → O(n log n) ground-action dedup.

**Key definitions.**

| Definition | File | Line | Replaces | What it does |
|---|---|---|---|---|
| `canon_code [code]` | `PDDL_Orderings.thy` | 132 | `sort (remdups xs)` (quadratic) | `remdups_adj (sort xs)` — O(n log n) dedup |

### 9. Speed 10: most-selective bucket pruning — `24ab5b4` (07-13 08:22)

**What.** When several argument positions of an atom are already determined, fetch the *smallest*
(most-selective) per-argument bucket instead of the leftmost one. Applied to both the closure join and
the `cert_ops` join.

**Why.** `cand_facts` narrowed candidates on only the leftmost determined position (`first_bound`); when
that position is non-selective the fetched bucket is large and the other positions are left to the linear
unifier. The smallest determined bucket is a strictly better starting candidate set.

**How.** `determined_ids` / `determined_ids_t` (all determined positions, not just the leftmost),
`shortest` (pick a shortest bucket, with `shortest_mem`), and a redefinition of `cand_facts` /
`cand_facts_t` to `shortest (map bucket determined_ids)`.

**Proof / verification.** `match_facts_idx_eq` / `pmatch_atom_idx_eq` re-proved under the new selector.
The completeness argument generalises for free: a matching fact carries *every* determined value, so it
lies in *every* determined bucket (`determined_ids_t_match` / the inner `inbkt` step) — hence in the
shortest one. Soundness is a subset of any bucket.

**Impact.** Fewer candidates per atom before unification ("variant A" of the bucket pruning; the
"variant B" full intersection over all bound positions is deliberately not done — it does not reduce the
join's branching factor, only pre-empts fast-failing unifier calls).

**Key definitions.**

| Definition | File | Line | Replaces | What it does |
|---|---|---|---|---|
| `determined_ids` / `determined_ids_t` | `Datalog_Certificate_Index.thy` / `Classical_Cert_Ops_Index.thy` | 39 / 36 | leftmost-only `first_bound` | all determined positions with their values |
| `cand_facts` / `cand_facts_t` (redef) | `Datalog_Certificate_Index.thy` / `Classical_Cert_Ops_Index.thy` | 57 / 54 | leftmost determined bucket | `shortest` (most-selective) determined bucket |

### 10. Speed 7 (closure): greedy reorder + permutation-invariance theorem — `4c8a8c0` (07-13 09:32)

**What.** Reorder each clause's body atoms most-constrained-first before the indexed join, so a
disconnected/seed atom cannot fan out before a constraining atom prunes it. This is the sprint's
genuinely-new verification result.

**Why.** The join is a left-deep nested loop; a bad atom order materialises large intermediates that are
later pruned. Processing the most-constrained atom first bounds the intermediate.

**How.** `reorder_atoms` (a `sort_key` permutation), and `body_join_idx [] (reorder_atoms …) idx` in the
safe branch of `dl_closure_check_exec_fast`.

**Proof / verification.** The core is a new characterisation of the join's substitution *set*, viewed
through `map_of`:
- `body_join_sound` — soundness companion to the existing `body_join_complete`: every assignment the join
  produces extends the seed, has domain exactly the seed's plus the joined atoms' variables, and grounds
  every atom into the facts.
- `body_join_map_of_char` — the `map_of`-image of the join equals the set of maps satisfying those three
  conjuncts, each depending only on `set atoms`.
- `body_join_map_of_perm` — therefore `mset atoms = mset atoms'` implies equal images.
The safe-branch predicate depends on the assignment only through `map_of` (`eval_guard_al_map_of_cong`,
`list_all_map_of_cong`), so `dl_closure_check_exec_fast_eq` stays a strict `=`. Proven live against the
`Datalog_Graph` heap; `Classical_Grounding` gated green.

**Impact.** Correctness of the reorder. The permutation-invariance theorem is the reusable core (it made
changes 11 and 12 nearly free).

**Key definitions.**

| Definition | File | Line | Replaces | What it does |
|---|---|---|---|---|

### 12. Speed 7+: index-driven selectivity key for the reorder — `c74dc4e` (07-13 11:09)

**What.** Upgrade the reorder sort key from a static proxy (number of variable arguments) to an
index-driven **seed candidate-set size** — sort atoms ascending by `length (cand_facts [] a idx)` (closure)
/ `length (cand_facts_t [] p ts idx)` (`cert_ops`), i.e. most-selective-first by actual RBT bucket size.

**Why.** The var-count proxy lets non-selective unary type atoms sort ahead of a constraining binary atom.
The seed candidate count is the atom's true selectivity at the empty binding.

**How.** Thread the in-scope `idx` into `reorder_atoms` / `reorder_pre`; the key becomes the candidate
count.

**Proof / verification.** No new proof obligation: `body_join_map_of_perm` / `pjoin_map_of_perm` already
cover *any* permutation, and `sort_key` with any key preserves `mset`, so the `_eq` code equations
re-prove unchanged — only `mset (reorder … idx …) = mset …` must re-hold, which it does.

**Impact.** Output byte-identical to the var-count key (confirmed empirically on logistics98-prob01), and
— honestly — the *same* ~32 s there: at the seed binding almost every logistics precondition atom is
all-variable, so its bucket is the full predicate bucket and the key barely discriminates. Logistics
selectivity is dynamic (it emerges only after the first variable binds), which a static seed-time key
cannot exploit. The principled next step is a dynamic, per-join-step reorder and/or a tree-decomposed
join (see below).

**Key definitions.**

### 13. The real HTG bottleneck: graph construction, not the DFS — `nat_edges_code`

`chk_acyclic` on GED `d-8-12` (model=1594) measured ~57 s. It looked like the per-vertex DFS
(`dl_acyclic_dfs` runs an independent DFS from every vertex, `O(V²)`), but the exported `nat_edges c =
map (λ(a,b). (fact_idx c a, fact_idx c b)) (dep_edges c)` with `fact_idx c = idx_of (dl_cert_facts c)`
**rebuilds `dl_cert_facts c` — an `O(R²)` `remdups` — inside every one of the `~2·|dep_edges|`
relabellings**, i.e. `O(|edges|·R²)`. `nat_edges_code [code]` (`Datalog_Cycle_DFS.thy`) binds
`dl_cert_facts` once with a `let` (`by (simp add: nat_edges_def fact_idx_def Let_def)`), dropping it to
`O(R² + |edges|·R)`. This sped up BOTH default checks. GED `d-8-12`, all variants byte-identical:
acyclicity `--gdfs` 111 s → ~140 ms, `--dfs` 57 s → 1.25 s, `--topo` 0 ms.

### 14. Three selectable foundedness checks — `ground [--dfs|--topo|--gdfs]`

`ground_via_cert_numeric_{dfs,exec,gdfs}_e` + `dl_certified_model_{dfs,exec,gdfs}`, all kept on purpose:
`--dfs` per-vertex `dl_acyclic_dfs` (`O(V²)`); `--topo` ordered scan `dl_founded_exec` over Nemo's topo
order; `--gdfs` the new fast single-sweep global-visited DFS `dl_acyclic_dfs_global`
(`Datalog_Cycle_DFS_Global.thy`, `O(V+E)`, one gray/seen set shared across roots, list-iterated
neighbours + balancing `RBT_Set.insert`/`delete` rather than the graph-lib join-based `insert_rbt`). Both
the list rewrite and `RBT_Set.insert` were *needed* but were **not** the bottleneck (see 13).

### 15–16. `dl_acyclic_dfs_global` fully verified (`0 sorry`)

`dl_acyclic_dfs_global_imp_acyclic` reduces (via `not_acyclic_dep_graph_imp_nat_edges`) to
`global_sweep_acyclic : dl_body_closed c ⟹ dl_acyclic_dfs_global c ⟹ acyclic (set (nat_edges c))` — the

### 14b. Closure streaming for head-only clauses — `combos_forall`

`dl_closure_check_exec_fast`'s unsafe branch materialised the whole `|U|^k` product of substitutions
(`cls_substs`) before testing any — the cost a head-only clause (empty body, head variables unbound by
any body atom: an action with a trivial precondition and effect parameters) pays. `combos_forall`
(`Datalog_Certificate_Index.thy`) fuses generation and testing with a short-circuiting `list_all`, never
building the product and stopping at the first violating assignment; proven equal to the abstract check
via `cls_substs_forall`, so the abstract `dl_closure_check_exec` soundness bridge is untouched.

### 17. Stream the ground-action schema expansion through the printer — memory

`numeric_ground_by_cert P M = numeric_ground_prob (P⇩T P) (canon (cert_ops_of_exec_fast (P⇩T P) M))`, and
`actions numeric_ground_dom = map2 numeric_ground_ac ops op_names` (`Numeric_Grounder.thy`) — each op (a
small name+args `ast_classical_plan_action`) expanded to a full ground schema (instantiated pre/eff via
`res_inst`). On action-list-bound domains (childsnack, satellite p33, organic-orig) that **schema list**
is the peak-RSS bottleneck; the `canon ops` list (the certificate that must stay materialised — `canon`
dedup+sorts it) is much smaller. Fix: three checks-only streaming grounders
`ground_via_cert_numeric_{dfs,exec,gdfs}_stream_e` — identical checks to the `_e` twins, but returning
`Inr (canon (cert_ops_of_exec_fast (P⇩T P) M))` (the ops) instead of the built problem — each with a
`_sound` theorem (`Inr ops ⟹ ∃M. ops = canon(…) ∧ numeric_ground_by_cert P M = numeric_P⇩G_cert P M`,
via `dl_certified_model_*_imp` + `numeric_ground_by_cert_eq`; **`0 sorry`**). The SML printer
`problemToStreamOps` then folds `numeric_ground_ac (P⇩T P)` over `ops` (`op_names =
distinct_strings_lit (length ops)`), building → printing → dropping ONE schema at a time. The printer is
untrusted output formatting (as always), so no new formatting proof is needed. Emitted bytes are
IDENTICAL (md5: gripper / blocks / rovers / GED × all three modes, and satellite p33's 3.97M-line
output). Peak RSS on satellite p33 `--topo`: **9.75 GB → 3.70 GB (−6 GB, ~2.6×)** — the saved delta is
exactly the materialised schema list.
